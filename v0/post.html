出发点：两种语言的同一种渴望

我是一个既写代码又写文章的人。白天，我用 TypeScript 和 Rust 构建软件；晚上，我用中文记录思考。 很长一段时间里，这两件事被放在完全不同的"容器"里——技术文档用 GitHub Pages 默认主题，文学作品发在公众号。

直到有一天我问自己：为什么不能有一个博客，既适合呈现一首诗的节奏，也适合展示一段代码的优雅？

这个问题的答案，就是 INK & CODE——"一本会写代码的杂志"。

好的设计是显而易见的，伟大的设计是透明的。好的排版让阅读成为一种享受，而不是一种任务。

— 设计哲学

设计系统：从 oklch 到 Newsreader

设计一个博客的主题比想象中复杂。你不仅要决定"好看"，还要决定"在什么情境下好看"。 一个技术文章的读者和一个文学作品的读者，他们的审美期待完全不同。

我最终确立的设计理念是：

  • 文学的温度：暖白纸色背景 + Newsreader 衬线体，像一本精心排版的杂志
  • 代码的理性：JetBrains Mono + 深色代码块，在浅色正文中自然区分但不突兀
  • 统一的节奏：oklch 色彩空间 + 8px 网格间距 + Major Third 字号比例

色彩：告别 HSL 的不均匀

如果你曾经被 hsl(240, 100%, 50%) 和 hsl(60, 100%, 50%) 之间的亮度差异困扰过， 你就能立刻理解为什么 oklch 是一个更好的选择。

在 HSL 中，相同 Lightness 值的黄色和蓝色看起来亮度完全不同——因为 HSL 的 Lightness 不是基于人眼感知的。而 oklch（以及它的前身 oklab）是感知均匀的： 相同 Lightness 在任何色相下，人眼看到的亮度是一致的。

展开查看：oklch vs HSL 的视觉对比原理

人眼对不同波长的光敏感度不同。我们对绿色最敏感，对红色次之，对蓝色最不敏感。 HSL 在计算 Lightness 时没有考虑这种差异，而 oklch 通过一个基于人眼视觉模型的变换矩阵来实现感知均匀。 这意味着设计师可以真正用 Lightness 来控制视觉层级，而不用担心色相的影响。

排版：四套字体的职责分工

一个常见的误区是"网站用两套字体就够了，一套衬线一套无衬线"。 但对于一个同时承载文学和代码的博客来说，这个分工不够精确。

我的做法是使用四套字体，各司其职：

  1. Newsreader（Display）：标题专用。现代衬线体有编辑气质，但字形不过于传统。支持可变字重和意大利体。
  2. Outfit（Body）：正文专用。几何无衬线，x-height 较大，适合长时间阅读。
  3. Plus Jakarta Sans（UI）：导航、标签、日期等 UI 元素的专用字体。人文主义无衬线体，在小字号下依然清晰。
  4. JetBrains Mono（Code）：所有代码的专用等宽字体，连字支持好，0 和 O 区分清晰。
css
/* 字体系统 CSS 变量 */
:root {
  --font-display: 'Newsreader', 'Georgia', serif;
  --font-body:    'Outfit', 'Segoe UI', sans-serif;
  --font-ui:      'Plus Jakarta Sans', sans-serif;
  --font-mono:    'JetBrains Mono', 'Fira Code', monospace;
}

/* 字号采用 Major Third 比例，base 18px */
:root {
  --text-xs:   clamp(0.625rem, 1.5vw, 0.7rem);
  --text-sm:   clamp(0.75rem, 1.5vw, 0.833rem);
  --text-base: clamp(0.95rem, 2vw, 1.063rem);
  --text-lg:   clamp(1.1rem, 2.5vw, 1.25rem);
  --text-xl:   clamp(1.3rem, 3vw, 1.5rem);
  --text-2xl:  clamp(1.6rem, 3.5vw, 1.875rem);
  --text-3xl:  clamp(2rem, 4vw, 2.375rem);
  --text-4xl:  clamp(2.4rem, 5vw, 3rem);
  --text-5xl:  clamp(3rem, 6vw, 3.75rem);
}

代码：深色背景中的理性之光

代码的呈现是这个博客最关键的挑战之一。如果处理不好，深色代码块在浅色背景中会像一个刺眼的补丁。 如果浅色代码与正文太接近，又会失去层次感。

我的方案是：

  • 行内代码：使用浅驼色背景 oklch(0.93 0.015 80)，保留正文的暖色调，但明确区分
  • 代码块：使用深蓝黑背景 oklch(0.18 0.01 265)，文字浅灰白，对比足够但不刺眼
  • 语言标签：代码块右上角显示语言，.code-block-wrapper__lang

下面是一个 JavaScript 示例，展示代码块在文章中的展示效果：

javascript
// 一个简单但实用的阅读时间估算函数
function estimateReadingTime(text, wpm = 225) {
  const words = text.trim().split(/\s+/).length;
  const minutes = Math.ceil(words / wpm);
  return minutes === 1 ? '1 min read' : `${minutes} min read`;
}

// 中英文混合文本也可以粗略估算
const article = `作为一个既写代码又写文章的人...`;
console.log(estimateReadingTime(article));
// → "6 min read"

再看一个 Rust 示例——展示类型定义和模式匹配：

rust
/// 文章类型枚举：技术文章 vs 文学作品
#[derive(Debug, Clone)]
enum ArticleKind {
    Tech { language: String, difficulty: u8 },
    Literature { genre: String, mood: String },
    Hybrid { tags: Vec<String> },
}

impl ArticleKind {
    fn reading_time(&self) -> &str {
        match self {
            ArticleKind::Tech { difficulty, .. } if *difficulty >= 7 => "12 min read",
            ArticleKind::Tech { .. } => "6 min read",
            ArticleKind::Literature { .. } => "8 min read",
            ArticleKind::Hybrid { .. } => "10 min read",
        }
    }
}

let post = ArticleKind::Hybrid {
    tags: vec!["设计".into(), "编程".into(), "写作".into()],
};
println!("{}", post.reading_time()); // → "10 min read"

实现：CSS 自定义属性的力量

整个设计系统通过 CSS 自定义属性（CSS Variables）驱动。所有颜色、字体、间距都是变量， 这意味着更换主题只需要在一处修改。

Any application that can be written in JavaScript, will eventually be written in JavaScript.

— Atwood's Law

同理，任何可以用变量表示的视觉属性，最终都应该用变量表示。

css
/* 一个示例：按钮组件完全由变量驱动 */
.btn--primary {
  background: var(--color-accent);
  color: var(--color-bg);
  font-family: var(--font-ui);
  font-size: var(--text-sm);
  padding: var(--space-sm) var(--space-xl);
  border-radius: var(--radius-sm);
  transition: background var(--duration-fast) var(--ease-out);
}

.btn--primary:hover {
  background: var(--color-accent-hover);
}

/* 如果要换主题色，只需改一个变量 */
:root {
  --color-accent: oklch(0.62 0.16 75); /* 琥珀金 */
}

/* 深色模式也可以是一套变量覆写 */
@media (prefers-color-scheme: dark) {
  :root {
    --color-bg: oklch(0.15 0.01 85);
    --color-text-primary: oklch(0.9 0.005 85);
    /* ... */
  }
}

结语：好设计是透明的

做这个博客的设计过程中，我最大的感悟是：好的设计不应该被注意到。 当读者沉浸在一篇文章中时，他们不应该意识到字体、间距、颜色的存在——这些东西应该像空气一样自然。

但是如果他们停下来想一想，他们会发现这个阅读体验是经过精心设计的。 每一处留白、每一个字号选择、每一个色彩 Token，都在为内容服务。

这大概就是"编辑风"博客的终极追求：让技术文章有杂志的质感，让文学作品有代码的精确。

CSS 不是一个简单的"美化工具"——它是一个排版引擎，而网页是它的画布。
